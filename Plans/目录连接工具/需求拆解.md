# 目录 ↔ 工具 直连（绑定同步）· 需求拆解

> 2026-10-31 · 状态：待评审 · 原型：`原型/本地目录连接工具-画布.html`
> 需求原文：目录、仓库等与工具直接建立连接——建连时目录中 skills 全部复制到工具；目录内容变化时自动监听、实时更新到工具。

---

## 0. 背景与目标

现状：skills → 工具是「勾选条目 → 选目标 → 复制/软链接」的**一次性手动动作**；目录内条目更新后需要重新手动分发。

目标：目录（本地源的多目录）与工具建立**持久绑定**——

1. 建连时：目录内全部 skills 同步到工具；
2. 之后：目录内容变化（外部增删改 / hub 内编辑）**自动监听并实时同步**到工具；
3. 全程有台账、有冲突保护、不碰非托管内容。

## 1. 既有管线复用面（本需求 80% 是"接线"，不是新造）

| 既有能力 | 位置 | 复用方式 |
|---|---|---|
| 本地目录 + 条目自动登记 | `local_dirs` / `registry_items.dir_id`（已上线） | 绑定的"源"侧直接用 |
| 分发目标 | `targets`（kind='skills_dir'，工具注册时自动生成，`origin='tool:<id>'`） | 绑定的"目的"侧直接用 |
| 分发引擎 | `distribute_skills(names, target_ids, mode)` | copy/link 互斥、幂等跳过、冲突停手、托管清单、备份、dry-run 全部现成 |
| 文件监听 | `FileWatcher`（链接目录已注册 `hub:localdirs` scope） | 变化感知直接用 |
| 台账 | `ops` | 新 action：`binding:bind` / `binding:sync` / `binding:unlink` |

**结论：不需要新的复制逻辑。** 需要新建的只有：绑定关系表、一个服务端同步 worker、绑定管理 UI。

## 2. 核心概念与关键约束

**绑定（binding）= 本地目录 × 分发目标 的持久关系**，携带写入方式与状态。

> ⚠️ 关键约束：**绑定对象是 target（目标目录），不是 tool。**
> Codex CLI 与 OpenCode 共享 `~/.agents/skills`（同一个 target）——绑定它 = 两个工具同时生效。
> UI 措辞用「目标目录」，并在工具列表里标注「共享」。

## 3. 用户故事

| # | 故事 | 验收要点 |
|---|---|---|
| US1 | 建连：目录管理 → 某目录「连接工具…」→ 勾选工具 → 连接并同步 | 目录全部 skills 出现在工具目录；报告 N 新增 / M 跳过 / K 冲突；记台账 |
| US2 | 自动同步：目录内改/增/删 → 数秒内工具目录跟随 | 改 SKILL.md ≤5s 更新；新增 skill 出现；删除 skill → 工具内**托管文件**移除；每次同步记台账 |
| US3 | 断连：断开绑定 | 默认**保留**工具内文件；可选「清理受管文件」（按托管清单，只删自己落过的） |
| US4 | 暂停/恢复：临时停用某绑定 | 暂停期间目录变化不传播；恢复后下次变化补齐 |
| US5 | 冲突：目标已有同名未托管内容 | 停手跳过并报告；force 才覆盖（先备份）；**绝不动非托管文件** |

## 4. 数据模型（零迁移，纯新增）

```sql
CREATE TABLE IF NOT EXISTS dir_bindings (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  dir_id INTEGER NOT NULL,              -- local_dirs.id
  target_id INTEGER NOT NULL,           -- targets.id（kind='skills_dir'）
  mode TEXT NOT NULL DEFAULT 'copy',    -- copy | link
  enabled INTEGER DEFAULT 1,            -- 0 = 暂停
  created_at TEXT NOT NULL,
  last_sync_at TEXT,
  last_result TEXT,                     -- JSON {added,updated,removed,skipped,conflicts}
  UNIQUE(dir_id, target_id)
);
```

## 5. 同步机制（服务端 worker，不依赖浏览器）

```
磁盘变化 → FileWatcher（已有，250ms 抖动）→【新增】内部订阅者守护线程
  ├─ 命中 scope hub:localdirs / hub:registry
  ├─ scan_sync(目录) → 得 added / updated / removed（已有）
  ├─ 查 dir_bindings（enabled=1）
  ├─ added+updated → distribute_skills(names, [target_id], mode)   ← 幂等，已同则 skip
  ├─ removed       → 按 deployments.detail.files 托管清单反向清理（只删自己落过的）
  └─ last_result + ops.log_op("binding:sync") + bump('tool:…') → UI 角标刷新
```

- 建连时的全量同步 = 同一函数的手动触发入口，不是另一条代码路径；
- worker 自身写入触发的 bump 不会自激（worker 只消费 `hub:localdirs`/`hub:registry` scope）；
- watcher 断档兜底（manifest 轮询）同样进队列 → 挂掉的变化也会补齐。

## 6. 冲突与边界

| 场景 | 行为 |
|---|---|
| 目标已有同名**未托管**内容 | conflict 停手（跳过 + 报告 + 台账）；勾选 force 才覆盖（旧内容先备份） |
| 目标文件被手动改过 | distribute 既有冲突语义（托管清单 diff） |
| 目录中删除 skill | 按托管清单清理目标内对应文件 + 空目录回收 |
| 断开绑定 | 文件保留（默认）；「清理受管文件」可选 |
| 移除目录（存在绑定） | 先提示解除绑定；确认移除 = 自动解绑 + 条目下架 + 磁盘不动 |
| 共享 skills_dir | 明示「此目录同时服务于 Codex CLI 与 OpenCode」 |
| 软链接模式回环 | 目标=链接指向本地目录，kqueue 对 symlink 目录的事件行为需先验证 → **放 M2** |
| hub 外编辑 SKILL.md | watcher 已监听 → 扫描 → hash 变 → 同步（与目录内实时同步同一链路） |

## 7. UI / 交互（见原型画布 ①–④）

1. **目录卡**：数量角标旁追加「→」+ 已连接工具色点（最多 3 个，多了 ∞）；
2. **目录管理弹窗 v2**：每行目录 + 已连接工具 chips（色点 + 名）+ `[连接工具…]`；行内已有绑定显示 `[暂停]` `[断开]`；
3. **连接工具弹窗**：说明行（全量同步 + 自动跟随 + 冲突策略）→ 工具多选列表（复选 + 色点 + 路径小注 + 共享标注）→ 写入方式（直接复制 / 软链接，M1 只有复制）→ 首次冲突策略（跳过并报告 / 覆盖）→ 主按钮「连接并同步 N 个 skill」；
4. **同步反馈**：toast「agent-skills → Claude Code：3 更新 · 1 新增 · 1 冲突」；台账 action=`binding:sync`；
5. 条目行**不**新增操作——绑定是目录级能力，条目级仍走手动分发。

## 8. 分期

- **M1（核心闭环）**：`dir_bindings` 表 + 建连/断连/列表 API + 建连全量同步 + watcher 同步 worker（仅 copy）+ 目录管理绑定 UI + 卡片连接标记 + 台账 + 冲突停手
- **M2**：软链接模式、暂停/恢复 UI、共享目录明示强化、同步失败徽章（黄点 = 上次失败，悬停看原因）、手动「立即同步」按钮
- **P2**：条目级排除（.hubignore）、双向变更合并策略、绑定健康总览（设置 → 工具侧）

## 9. 验收标准

1. 建连 → 工具目录出现全部 skills（含子文件），报告准确；
2. 改 SKILL.md 保存 → ≤5s 工具内更新；新增 / 删除 skill → 工具内出现 / 托管文件移除；
3. 未托管同名内容零接触；force 之外绝不覆盖；
4. 断开后工具文件保留；勾选清理则托管文件移除；
5. 服务重启后 worker 自动恢复；重复同步幂等；
6. 判据：绑定 CRUD、初始同步、三态传播、冲突停手、断开保留、共享 target 一次同步两工具生效。

## 10. 开放问题（需拍板）

| # | 问题 | 建议 |
|---|---|---|
| 1 | 建连时默认冲突策略 | 跳过并报告（安全默认，force 留给高级） |
| 2 | 目录内删除是否默认传播到工具 | 默认开（托管清单已保证只删自己的） |
| 3 | 断连时提供「清理受管文件」？ | 提供，默认不勾 |
| 4 | 软链接模式进 M1 还是 M2 | M2（先验证 kqueue 对 symlink 目录的事件） |
| 5 | 一个目录能否绑定共享 target | 能，但 UI 必须明示双工具同时生效 |
