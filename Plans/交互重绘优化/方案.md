# 交互优化：从「整块重绘」到「局部更新」

> 状态：**待确认**（2026-10-17，动手前先过一遍）
> 依据：`DESIGN.md §交互动效原则` 第 2 条「不整块重绘」——动作只改被操作的节点，整表重绘会换掉节点，过渡当场消失。
> 相关：`FIGMA_OVERRIDES.md`（用户指令覆盖稿子）、`DESIGN.md §动效`（时长 token）

## 1. 现状（有据可查）

| 位置 | `await refresh()` 调用点 | 说明 |
|---|---|---|
| `web/views/skills.js` | 28 | 拉取 / 安装 / 更新 / 删除 / 搜索 / 翻页 / 展开来源 / 手动条目增改 |
| `web/views/mcp.js` | 25 | 同上（写入 / 验证 / 连接测试） |
| `web/views/settings.js` | 6 处 `renderTools()` | 保存 / 启停 / 删除后重绘整张工具表 |
| `web/app.js` | 9 处 `renderAll()` | 会话页筛选、迁移、刷新采集 |
| `web/views/memory.js` / `ops.js` | 0 | 各自内部处理 |

**`refresh()` 实际做了什么**（skills/mcp 同构）：

```js
async function refresh() {
  await api('/api/ops?...');                 // 台账
  await loadAll();                           // 来源 + 目标 + 条目 + 登记表
  renderLeft(); renderCenter(); renderRight();   // ← 三个容器整块 innerHTML 重绘
  syncShell(...);                            // ← 顶部卡片组 + 统计条重绘
}
```

也就是说：**改一条数据 = 重画整页 4 个区域**。代价三件事：

1. 列表节点全换 → 展开态（手风琴）丢失，动画看不到；
2. 滚动位置丢（已临时补救：`keepTop` 快照/还原）；
3. 交互中断感：搜索框失焦、正在拖的排序被打断、按钮的 `is-loading` 被抹掉。

## 2. 方案（分三步，每步都可独立验收）

### 步骤 A：给 refresh 加「局部更新」入口（不改现有调用）

新增两个可选参数，默认行为完全不变（向后兼容，风险最低）：

```js
// 局部刷新：只重画受影响的区域，并保留展开态/滚动/焦点
async function refresh(opts = {}) {          // opts: { parts: ['rows'|'cards'|'targets'|'ledger'] }
```

并把「展开态」「滚动位置」「搜索框焦点与光标位置」统一收进快照/还原：

```js
const snap = snapshotView();   // { scroll, focusId, caret, expandedId, selected }
... 只重画 parts 指定的区域 ...
restoreView(snap);
```

验收：现有 28 + 25 个调用点不动，E2E 全绿；手工验证搜索时不失焦、展开态不丢。

### 步骤 B：逐类操作切到局部刷新（按"用户高频"排序）

| 批 | 操作 | `parts` | 预期收益 |
|---|---|---|---|
| B1 | 搜索 / 翻页 / 折叠来源 / 展开条目 | `['rows']` | 输入不再被打断，列表不跳顶 |
| B2 | 安装 / 更新到工具 / 写入 | `['rows','targets','ledger']` | 行内进度可见，右侧目标矩阵就地变化 |
| B3 | 手动条目 新建 / 编辑 / 删除 | `['rows','cards','ledger']`（删除额外走行收起动画） | 新增行有入场，删除行收起后移除 |
| B4 | 远程拉取（会新增/删除多个条目） | `['cards','rows','targets','ledger']` + 结束后 `flashChanges` | 变化可视化（复用磁盘变动高亮那套） |
| B5 | 设置页工具保存 / 启停 / 删除 | 只改被操作行（已有 `flipToggle` / 就地更新） | 整表不再重绘，拖拽排序不被打断 |

### 步骤 C：长任务改「就地进度」

拉取 / 批量安装这类会跑几秒的操作：
- 按钮进入 `is-loading`（已支持），**不**触发整页刷新；
- 每次后端返回结果项 → 就地更新对应行的状态胶囊（而不是等全部完成后重画）。

## 3. 风险与对策

| 风险 | 对策 |
|---|---|
| 局部更新后数据与视图不一致（例如统计条没更新） | 每个 `parts` 组合在 `refresh` 内部**断言**一遍该区域的渲染函数被调用；E2E 加「操作后统计条数值同步」断言 |
| 展开态/选中态恢复错位（条目已被删） | `restoreView` 按 key 找节点，找不到就静默跳过 |
| 与磁盘变动 SSE 刷新叠加（两个来源同一时刻刷） | 统一走同一个 `refresh({parts})`，并用现有 250ms 抖动合并；SSE 侧继续用 `flashChanges` 标变化 |
| 改动面大（60 处） | 分 5 批提交，每批跑一次 `tests/run_all.sh`；任一批红了先回滚该批 |

## 4. 验收标准

1. 高频操作（搜索、展开、安装、删除）**无整页闪烁**、滚动/展开/焦点保持；
2. 每次操作后 `window.__hubErrors` 为空（防上次 `keepTop` 那类错）；
3. E2E：现有 17 条 + 沙箱 13 条全绿（含 npm 环境项说明）；
4. 新增 3 条交互断言：搜索不失焦、展开态保持、删除行收起后移除。

## 5. 工作量估算

| 步骤 | 内容 | 规模 |
|---|---|---|
| A | `refresh(opts)` + 快照/还原 + 向后兼容 | ~120 行，1 批 |
| B | 5 批调用点切换 | 每批 ~30–60 行改动 |
| C | 长任务就地进度 | ~80 行，1 批 |

先做 A + B1（收益最高、风险最低），确认手感后再推 B2–B5。
