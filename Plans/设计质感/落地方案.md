# 从「模糊的样式想法」到「AI 实现高质感界面」——落地流程方案

> 核实日期：2026-10-16 · 适用项目：Agent Depot（及同类**工具型**本地应用）
> 目标：建立一条可复用的能力链，让「我有个模糊感觉」→「AI 做出美观且好用的界面」不再靠运气。

---

## 一、结论先说：用什么、不用什么

| 环节 | 采纳 | 理由 |
|---|---|---|
| **方向探索** | Claude Code 内置 `/design` | 无需安装、多方案并排可编辑、选定后直接进代码 |
| | 参考站截图（Mobbin / Land-book / Godly 等） | 非设计师最省力的"表达感觉"方式 |
| | `hallmark study` | 把欣赏的设计提成"设计 DNA"，导出 `design.md` |
| **规范固化** | 手工写进 `tokens.css` + `DESIGN.md` | 已有体系，不再生成第二套 |
| **实现约束** | 现有 `AGENTS.md` + 补「场景旋钮」+「产出前自评」 | 两个机制都来自成熟 skill，纯文档零依赖 |
| **质量审计** | `hallmark audit`（57 关） | 一次性体检现有界面 |
| | `ui-redesign` 的规则目录与「三旋钮」 | **最匹配本项目**，见下 |
| | 现有 `lint_styles.py` | 机检兜底，继续扩 |
| **明确不用** | ❌ `frontend-design`、`hallmark build`、`repaint` 的 build | 它们追求"**每页都不同指纹**"，与本项目"工具型界面必须高度一致"**直接冲突** |
| | ❌ Aioli Design、Design Intelligence MCP、各类设计系统生成器 | 会产出第二套设计系统，与 `tokens.css` 打架——就是我们刚避免过的"双份真源" |
| | ⚠️ `cc-design-cli` | 机制好（风格画廊），但要 `npx` + 常驻 MCP；**按需再装**，非必需 |

## 二、核实结果（逐个查证）

| 工具 | 状态 | 关键事实 |
|---|---|---|
| **Claude Code `/design`** | ✅ 真实 | Anthropic 2026-08-18 发布的 research preview。终端里生成多张可编辑 artboard，选定→直接在 codebase 实现。**零安装**（你已在用 Claude Code）。Pro/Max 等付费档可用 |

| **ui-redesign** `rashee1997/ui-redesign` | ✅ 真实 | **323 条规则 / 27 类** + **6 道关卡流水线**（G0 范围→G1 调研→G2 计划→**G3 用户批准**→G4 实现→G5 验证，产物落 `.ui-audit/`）+ **三个旋钮**（见下）。装在 `.agents/skills/` |

**一个额外收获**：`ui-redesign` 与 `repaint` 各自独立地提出了同一个概念——**先给界面定"场景基调"再谈好看**。这正是本项目的关键，见 §四。

## 三、核心概念：界面分场景，好标准不同

工具型应用（本项目）与营销落地页的"好"是**相反**的：

| 维度 | 营销页 / 落地页 | 工具型应用（**本项目**） |
|---|---|---|
| 布局变化 | 越大越好，每页不同指纹 | **小**——列表页就该长得像列表页 |
| 动效 | 多，营造氛围 | **少**——只为解释状态变化 |
| 信息密度 | 稀疏、留白 | **高**——一屏看尽可能多 |

`ui-redesign` 把这三件事做成了 1–10 的旋钮，并给了预设：

- **DESIGN_VARIANCE**（布局变化度）· **MOTION_INTENSITY**（动效强度）· **VISUAL_DENSITY**（密度）
- **内部工具 / 仪表盘预设：VARIANCE 3-4 · MOTION 2-3 · DENSITY 8-9** ← 本项目取这组
- 对照：B2B SaaS 视图 6-7 / 5-6 / 4-5；营销页更高

**所以：凡是被贴上"反 AI 味、拒绝模板化"标签的工具，其 `build` 能力对本项目都是反作用。** 能用的是它们的 **audit / study / 规则库**。

## 四、目标流程：五步链路

```
S0 定基调  →  S1 找方向  →  S2 固规范  →  S3 让 AI 实现  →  S4 质检  →  S5 回灌
（场景旋钮）  （看和选）   （tokens+DESIGN）（带约束生成）  （审计）    （加规则）
      └──────────────────── 不满意就回到上一步 ────────────────────┘
```

### S0 · 定基调（一次性，写进 `DESIGN.md` 开头）

**动作**：声明这类界面属于什么场景，据此锁死三个旋钮值。
**本项目取值**：`VARIANCE 3 / MOTION 2 / DENSITY 8`（内部工具预设）。
**为什么先做**：不定基调，AI 会照培训数据里最泛滥的"营销页审美"发挥——大留白、紫渐变、卡片阵。
**产出**：`DESIGN.md` 新增「场景基调」一节。

### S1 · 找方向：把「感觉」变成「可选项」

三条路，按省力排序：

1. **Claude Code `/design`**（首选，零安装）
   直接说 `/design 给 XX 页面出几版方向`。它在终端生成多张可编辑画板，你并排比较、挑一个、当场微调。
   *这是"非设计师"最直接的表达方式——不用描述，只用选。*
2. **逛参考站截图**（最原始但最有效）
   去 Mobbin / Land-book / Godly / Refero 找同类产品，截图丢进 `原型/参考/`，说"就这种感觉"。
3. **`hallmark study`**（把参考自动化）
   指一个欣赏的网站/截图，它提取宏观结构 + 字体搭配 + 色彩锚点，导出 `design.md`。
   *它明确不做像素级克隆、不识别具体字库——提取的是"设计骨骼"不是皮肤。*

**产出**：1 个选定的方向 + 3–5 张参考图存 `原型/参考/`。

### S2 · 固规范：方向 → 可执行数值

**动作**：把选定的方向翻译成具体值，两层落位：

| 落到哪 | 写什么 |
|---|---|
| `web/tokens.css` | 色彩锚点、字体对、间距节奏、圆角、动效时长（**只有值**） |
| `DESIGN.md` | **何时用 / 何时不该用**（散文部分，这才是 token 之外的另一半） |

**注意**：若 S1 得到的方向与现有 `Muller-Brockmann 网格功能主义` 冲突，**先改 DESIGN.md 的方向声明，再改值**——别让文档与代码各说各话。
**不要**用 Aioli 之类生成第二套 token 体系。

**产出**：更新后的 `tokens.css` + `DESIGN.md`。

### S3 · 让 AI 实现：带着约束生成

**现有基础**：`AGENTS.md` 6 条硬规则 + `DESIGN.md §11` 禁止项，已能拦住硬编码色值、原生弹窗这类最低级问题。

**要补两样**（都来自成熟 skill 的机制，纯文档、零依赖）：

1. **把场景旋钮写进 `AGENTS.md`**
   > 本项目是工具型应用：布局变化度 3 / 动效强度 2 / 信息密度 8。不要为每个页面追求不同的"指纹"。
2. **加一条「产出前自评」**（借 Hallmark 的 pre-emit critique）
   > 交活前对照 `DESIGN.md §11` 逐条自查，并对这 6 项自评 1–5 分：**主张 / 层级 / 执行 / 具体性 / 克制 / 变化**；任一项低于 3 分，先改再交。

**产出**：界面代码 + 一次自评记录。

### S4 · 质检：三条独立视角

| 视角 | 用什么 | 看什么 |
|---|---|---|
| AI 味 | `hallmark audit` | 57 道关卡：紫渐变、居中毒、卡片阵、重画浏览器 chrome… |
| 工程与交互 | `ui-redesign` 规则目录（323 条 / 27 类） | 状态齐全、表单守卫、WCAG 2.2 AA 对比度、focus 环、动效 ≤250ms、认知负荷 ≤7 项 |
| 机检 | `python3 tests/lint_styles.py` | 裸色值 / px 字号 / 裸 z-index（已 CI 化） |

**`ui-redesign` 的 6 道关卡值得借鉴**，尤其 **G3「用户明确批准后才动代码」**——把"选方向"和"写代码"physical 分开，正是 `/design` 的思路。

**产出**：问题清单 → 回 S3 或 S2。

### S5 · 回灌：不满意就加规则

每出现一个"AI 这么写我不满意"的决策，就加一条进 `DESIGN.md §11`。
这与那份对话的收尾建议一致：**"每产出不满意决策，就加一条规则"**——规范是长出来的，不是一次写完的。

## 五、落地顺序（建议）

| 优先 | 做什么 | 成本 | 收益 | 状态 |
|---|---|---|---|---|
| 1 | `DESIGN.md` 加「场景基调」节（三旋钮取值） | 10 分钟 | 一次性解决"该像工具还是像落地页"的混淆 | ✅ **2026-10-16 已落地**（DESIGN.md §0.1） |
| 2 | `AGENTS.md` 加「产出前自评」+ 旋钮提醒 | 10 分钟 | 把事后 lint 前移成事中自查 | ✅ **2026-10-16 已落地**（AGENTS.md 第 1 条 + 第 6 条） |
| 3 | 试一次 `/design` 出多方向 | 半小时 | 验证"看和选"这条路对你是否顺手 | ⏳ 待做 |
| 4 | 跑一次 `hallmark audit` 体检现有界面 | 半小时 | 拿到 57 关的具体扣分项，纯读不改 | ⏳ 待做 |
| 5 | 视结果补 `lint_styles.py` 规则（如对比度、间隔 4 倍数） | 按需 | 把审计结论固化成机检 | ⏳ 待做 |

**1、2 是纯文档，已经做完**——现在 AI 读到 `AGENTS.md` 时，会先知道"这是工具不是落地页"，并在交活前做一次自评，而不是等 lint 报错。

## 六、遗留风险

- **所有 skill 都在 agent 侧**（`~/.claude/skills/` 等），**不进项目依赖**，与"零依赖、离线可用"原则不冲突；但换机器要重装。
- `/design` 是 research preview，**能力与可用档位可能变**，别把流程全押在它上面（S1 有两条备选）。
- `hallmark audit` 是针对**营销页审美**训练的，它会建议你"加纹理、破对称、多点动效"——**这些建议要按 §三 的场景表筛掉**，不要照单全收。
- 本方案只核实了 6 个工具，其余同名同类工具未验证，采用前先查。
