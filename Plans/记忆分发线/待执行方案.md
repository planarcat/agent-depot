# 记忆分发线 · 待执行方案

> 依据：[第1轮-核心原则.md](./第1轮-核心原则.md)、[第2轮-需求确认.md](./第2轮-需求确认.md)
> 状态：**已执行**（M1→M2→M3 于 2026-10-12 一次到底完成，见文末「执行落地记录」）
> 原则：读取 → 中间体 → 写入；hub 权威源；能力探测驱动 UI；自动化优先、手动兜底

## 一、架构总览

```
左栏（来源）                      中间体（hub）                 右栏（去向）
各工具记忆文件  ──能力探测+扫描──▶  登记表 + 内容库  ──编辑/分发──▶  各工具记忆文件
（可读点亮/不可读置灰）           （hash 锚点、权威源）          （可写显示/不可写隐藏）
```

- 中间体 = hub.db 登记表 + hub 库目录内的 markdown 内容文件（与 Skills 本地库同构）
- 一切显示以设置页的工具启停为总开关

## 二、数据模型

- `memory_items`：id、kind（user_profile / project_memory）、scope（global / 项目标识）、name、version、hash、source_tool、source_path、updated_at、status（ok / drifted / conflict）
- 内容文件：`~/.agent/hub/memory/<scope>/<name>.md`，树 hash 与登记表互相校验
- 每次写回记录 `memory_deployments`（item、目标工具、写出 hash、时间）——漂移检测的基准

## 三、后端：新模块 mod_memory

1. **能力探测**：逐工具探测记忆目录（路径存在？可解析？可写？），结果存工具表，驱动 UI 点亮/置灰/隐藏
2. **扫描采集**：读工具记忆文件 → 解析为中间条目 → 首次导入登记；此后扫描只做对账（内容与上次写出的 hash 比对 → 正常 / 漂移）
3. **编辑**：hub 内编辑中间条目 → 更新 hash
4. **分发写回**：中间体 → 各可写工具的原生格式/路径；写回前 hash 校验，冲突人工选边
5. **扫描护栏**：单工具扫描超时约 3 秒或超量 → 该工具标记「手动刷新」，不拖累整体

工具路径适配采用**探测制**：Trae CN 路径已知（`~/.trae-cn/memory/`）；其余工具实施时逐个探测，探不到就是「不可读置灰 / 右侧隐藏」，不报错不阻塞——这正是探测制的价值。

## 四、前端：记忆页

- 左右双栏布局（沿用 Skills 页的视觉与交互语言、摘要小字、分页修复成果）
- 左栏来源列表：可读工具点亮可点，不可读置灰；右栏去向列表：只显示可写工具
- 进入页签自动刷新列表；会话正文懒加载；手动刷新按钮常驻
- 条目操作：查看 / 编辑 / 分发；漂移条目显著标记

## 五、Skills/MCP「拉取即落库」（同方案内顺手改）

- `pull_source` 成功后自动物化新增/变更条目进本地库（非 force，本地有改动标记冲突）
- `distribute_skills` 遇到未落库条目自动物化后再分发（兜底）
- MCP 不涉及

## 六、分期与验收

| 期 | 内容 | 验收标准 |
| --- | --- | --- |
| M1 | mod_memory（探测+扫描+中间体）+ Skills 拉取即落库 | 打开记忆页能看到各工具记忆条目与可读状态；Skills 从源拉取后无需二次点击即可分发 |
| M2 | 记忆页前端（左右布局、自动刷新、降级按钮） | 进入页签自动出数据；不可读置灰、不可写隐藏；超时工具降级手动且其余不受影响 |
| M3 | 写回分发 + 漂移检测 | 能把用户画像写回可写工具；外部改动被标记漂移且不静默覆盖 |

## 七、风险与对策

- **工具记忆路径随版本变化** → 探测制天然容错，探不到置灰而非报错
- **工具频繁自写记忆导致漂移频发** → 漂移是提示不是阻断；后续可加「以此为准」一键认领
- **隐私外铺** → 右栏所见即所得，分发动作显式确认
- **大库性能** → 超时降级 + 懒加载正文

与方案的偏差：
- 中间体内容文件实际落 `~/.agent/hub/memory/store/<scope>/<tool>__<kind>.md`（多一层 store/，避免与 legacy 笔记日志混在同一目录）
- kind 增加 `topics`（Trae CN 项目话题文件），status 取值实际为 `ok | drifted`（冲突态由分发时的确认流程承担）
- 项目级条目 scope 即工具侧真实项目目录名，写回仅支持源工具自愈回写（跨工具项目记忆无对应目录，不做）
