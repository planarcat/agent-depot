# 自动中转：性能测试报告与数据目录结构

> 日期：2026-10-21
> 结论：**采用「即时监听 + 自动转存」**（事件驱动 + 1 秒指纹兜底轮询）
> 适用版本：Agent Depot v0.6（hub 服务，纯标准库 Python）

---

## 一、要解决的问题

工具（Claude Code / Codex CLI / OpenCode / WorkBuddy / ZCode / AutoClaw / Pi-Agent / Cursor 等）在本地写会话记录。
hub 需要把这些记录**自动收进自己的应用目录**，供浏览、搜索、迁移、记忆提取使用。

需要回答的问题：
1. 从文件发生变化，到内容完成转存，需要多久？
2. 对超长会话（几十 MB、上万条消息）的增量追加，代价是否随文件变大而变慢？
3. 常驻监听本身会不会明显占用 CPU / 内存？

据此在三种方案中选择：
- A. 即时监听并转存
- B. 即时监听，定时批量转存
- C. 仅手动转存

---

## 二、测试方法

### 2.1 环境与数据

- 合成一份 Claude 会话 JSONL：**48 MB / 12,791 条消息**
- 使用与生产完全相同的扫描器（ClaudeScanner）和 SQLite 存储
- 全程在临时目录中进行，不改动真实会话文件与真实数据库
- 扫码链路包含：读取增量片段 → 逐行 JSON 解析 → 角色/正文归一化 → 写入标准化消息表 → 去重

> 注意：本文测的是「**格式转换 + 标准化入库**」，不是原文照搬；也**不包含**跨工具迁移（把会话写成 Codex/OpenCode 等目标格式）。

### 2.2 测试项

| 测试项 | 说明 |
|---|---|
| 首次全量转存 | 空库导入 48MB 会话 |
| 无变化空扫 | 文件没变，再扫一次的开销 |
| 增量 +1 条 | 在文件末尾追加约 4KB 的一条消息 |
| 增量 +1MB | 追加约 250 条消息 |
| 事件监听时延 | 文件写入完成 → 监听事件到达订阅端 |
| 兜底轮询时延 | 监听漏掉追加时，指纹轮询发现变化 → 完成转存 |
| 全工具空转 | 一次对全部已启用工具做空扫 |
| 指纹轮询开销 | 每秒对所有会话来源做一次 stat 比对的成本 |
| 常驻开销 | hub 空转 10 秒的 CPU 时间与内存占用 |

---

## 三、测试结果

### 3.1 转存耗时

| 场景 | 耗时 |
|---|---|
| 首次全量转存 48MB / 12,791 条 | **770 ms**（CPU 488 ms） |
| 无变化空扫 | 0.2 ms |
| 增量 +1 条（约 4KB） | **0.2 ms** |
| 增量 +1MB（约 250 条） | **6.6 ms** |
| 单个工具首次补采（积压） | Claude 1.5ms · Codex 1.3ms · WorkBuddy 84ms · ZCode 226ms · Pi 265ms |
| 全部工具空转一次 | 约 23 ms |

**关键结论：增量成本只和“新增了多少”有关，与文件总长度无关。** 超长上下文不会拖慢增量转存。

### 3.2 监听与轮询时延

| 路径 | 时延 |
|---|---|
| 事件驱动（监听命中 → 触发扫描） | 约 **290 ms**（含 300ms 防抖） |
| 兜底轮询（1 秒周期） | **≤ 1.4 s** |
| 实测启动补采 | 停机期间积压 **5,678 条消息，749 ms 补完** |

### 3.3 常驻开销

| 指标 | 实测 |
|---|---|
| hub 空转 CPU | 10 秒消耗 0.07 秒 CPU ≈ **0.7% 单核** |
| hub 内存（RSS） | **11.5 MB** |
| 指纹轮询一次 | 约 4–10 ms（只做 stat，不写库） |

### 3.4 方案判定

按预设的三档规则：

| 条件 | 实测是否满足 |
|---|---|
| 转存快、超长上下文增量不退化 | 满足（单条 0.2ms，与文件大小无关） |
| 常驻监听开销可忽略 | 满足（约 0.7% CPU / 11.5MB） |

→ **选择 A：即时监听并转存。**

## 四、实现方式

### 4.1 为什么还要一个“兜底轮询”

macOS 自带的 kqueue 监听有两个盲区：
1. 只监听目录的直接子项，**深层目录里的文件追加看不到**（例如 `projects/<项目>/<会话>.jsonl` 的追加）；
2. SQLite 工具的写入先落在 `-wal` 文件，主库文件的修改时间可能不变。

因此不能只靠文件事件。最终采用两层：

```
文件变化
  ├─ 事件命中（约 0.3s）──┐
  └─ 每秒指纹比对（≤1s）──┴─→ 只扫描发生变化的工具 → 增量入库 → 通知界面刷新
```

- **事件驱动**：监听命中 `tool:<工具>` 后，合并 300ms 内的抖动，只扫该工具；
- **指纹轮询**：每秒对每个工具的会话来源做一次 `路径 + 修改时间 + 大小` 比对，
  只有变化才扫描；空转时不写数据库；
- **启动补采**：服务启动后先补一次，收进停机期间产生的新消息。

### 4.2 可调参数

| 环境变量 | 默认 | 作用 |
|---|---|---|
| `HUB_INGEST_AUTO` | 开启 | 设为 `0` 退回纯手动转存 |
| `HUB_INGEST_POLL` | `1.0` | 指纹兜底轮询周期（秒） |

### 4.3 已知边界

- 监听事件本身有约 0.3 秒防抖延迟，属于有意设计（避免一次批量写入触发多次扫描）；
- 写入频率极高的长会话，会按防抖窗口合并成一次扫描；
- 跨工具迁移、记忆/Skills/MCP 的写入仍走各自原有链路，不在本自动转存范围内。

## 五、各模块的目录结构

### 5.1 应用根目录

| 环境 | 路径 |
|---|---|
| 正式版 | `~/.agent-depot` |
| 开发版（`run.sh` 默认） | `~/.agent-depot-dev` |
| 显式覆盖 | 环境变量 `AGENT_DEPOT_HOME`（兼容旧 `AGENT_HUB_DIR`） |

**所有持久化数据都在这个根目录下**，不散落到其他位置。

### 5.2 总览

```
~/.agent-depot-dev/
├── hub.db                 主数据库（会话、消息、游标、台账、迁移、记忆索引、配置）
├── hub.db-wal / -shm      SQLite 运行时文件（自动生成）
├── exports/               会话导出文件（按需生成，可随时清理）
├── memory/                记忆模块
│   ├── YYYY-MM-DD.md      每日记忆日志（人类可读，追加式）
│   └── store/             记忆中转库（中间格式，按作用域分目录）
│       └── <作用域>/
│           └── <工具>__<类型>.md
├── registry/              本地条目库（Skills / MCP 的“唯一出货口”）
│   ├── skills/<条目名>/   本地 Skill 内容（SKILL.md 及附属文件）
│   ├── mcp/<条目名>.json  本地 MCP 配置
│   └── .versions/         覆盖前的版本备份
│       ├── skills/<条目名>/<时间戳>/
│       └── mcp/<条目名>/<时间戳>/
└── sources/               远程 Git 源缓存（拉取即落库）
    ├── skills/<仓库名>/   如 planarcat-agent-skills、planarcat-lingchuang-skills
    └── mcp/<仓库名>/     不同分支/子目录追加后缀区分
```

### 5.3 会话中转

| 内容 | 位置 |
|---|---|
| 会话主记录 | `hub.db` → `sessions` 表 |
| 消息正文（已归一化） | `hub.db` → `messages` 表（按 `sid + 内容哈希` 去重） |
| 增量游标（读到哪里） | `hub.db` → `cursor` 表（工具 + 源文件 → 字节偏移/序号/时间） |
| 迁移记录 | `hub.db` → `migrations`、`lineages` 表 |
| 导出文件 | `exports/`（按需生成，清理后下次导出自动重建） |

原始会话文件仍在各工具自己的目录里（只读）；hub 只保存转存后的标准化副本。

### 5.4 记忆中转

| 内容 | 位置 |
|---|---|
| 记忆索引与正文 | `hub.db` → `memories`、`memory_items`、`memory_deployments` 表 |
| 中间格式内容 | `memory/store/<作用域>/<工具>__<类型>.md` |
| 每日可读日志 | `memory/YYYY-MM-DD.md` |
| 旧版单条笔记 | `memory/<时间戳>-note.md`（历史遗留，保留兼容） |

作用域示例：`global`（用户级）、`project-<哈希>`（项目级）。

### 5.5 Skills

| 内容 | 位置 |
|---|---|
| 本地库（手动 + 拉取后的收编） | `registry/skills/<条目名>/` |
| 版本备份 | `registry/.versions/skills/<条目名>/<时间戳>/` |
| 远程源缓存 | `sources/skills/<仓库名>/`（Git 工作副本） |
| 源与条目登记 | `hub.db` → `sources`、`items`、`registry_items` 表 |
| 分发记录 | `hub.db` → `targets`、`deployments` 表 |

### 5.6 MCP

| 内容 | 位置 |
|---|---|
| 本地库 | `registry/mcp/<条目名>.json` |
| 版本备份 | `registry/.versions/mcp/<条目名>/<时间戳>/` |
| 远程源缓存 | `sources/mcp/<仓库名>/` |
| 源与条目登记 | 同上，与 Skills 共用 `sources`、`items`、`registry_items` |
| 分发记录 | 同上，与 Skills 共用 `targets`、`deployments` |

### 5.7 台账与配置

| 内容 | 位置 |
|---|---|
| 操作台账 / 扫描记录 | `hub.db` → `ops`、`ledger` 表 |
| 工具注册、计划任务、界面状态 | `hub.db` → `config` 表 |
| 结构快照 | `hub.db` → `snapshots` 表 |

## 六、回归检查清单

1. 重启 hub 后 `/api/watch` 的 `ingest.running` 为 `true`，启动补采有新消息时 `messages` 增长；
2. 在任一工具产生新消息，界面应在约 1 秒内自动出现新会话/新消息，无需手动“刷新”；
3. 停掉 hub 一段时间再启动，停机期间的会话应被补采；
4. `HUB_INGEST_AUTO=0` 启动后不再自动转存（手动刷新仍可用）；
5. 检查 `~/.agent-depot-dev` 与 `~/.agent-depot-dev/registry/.versions` 等目录，确认没有数据写到应用目录之外。
