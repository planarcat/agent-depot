## 用户提问

行，先处理质量体系的事，按 A 做。

## 背景与分析

「方案 A」指上一轮（会话内，落盘前）对比的变异测试三条路线中的 A：**用 Python 标准库自研零依赖变异器**。另外两条是 B（用 `uv tool` 装 cosmic-ray）和 C（mutmut，因只支持 pytest、在进程内切换变异，被否决）。

这一决定意味着：

- 第 1 轮推荐的「xtask（Rust）质量工具链」**暂不作为第一块**。后端转向 Rust 是确定的方向，但排在质量体系补齐之后。
- 质量体系补齐两个缺口，都用 Python 标准库完成，不引入依赖：
  1. **变异门禁**（落地方指南 §四）：`scripts/mutate.py`
  2. **lint 基线**（落地方指南 §三-3）：`scripts/lint_baseline.py`。要考虑以后接上远程仓库、多分支并行的场景，也就是只比对「本次变更文件」、合并期不误报、rebase 不误报。

## 建议与回答

- 变异器按「`ast` 定位变异点 → 按源码字节区间替换（保留原格式与注释）→ 在隔离副本里跑指定测试」实现。第一批只盯测试为绿的模块（`hub/watcher.py` ↔ `test_watcher`、`hub/lib/mcpverify.py` ↔ `test_mcp`）。
- 将来迁到 Rust 时：
  - `mutate.py` 的 Python 变异部分随 Python 一起下线，Rust 代码改用 `cargo-mutants`。
  - 计分口径与阈值（high 80 / low 60 / break 60）沿用，方便前后对比。注意：自研规则集的得分**不能和 Stryker / mutmut 横向比较**。
