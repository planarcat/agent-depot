| 内容搜索搜不到夹具 | **测试失效** | `BUILTIN_TOOLS` 里 workbuddy/zcode/autoclaw **自带 `root: ~/...`**，scanner 走 `self.root or env` → env 覆盖无效 → 测试扫真实会话，真实数据把夹具挤出 top 40 |

最后一条最值得记：它同时是「隐私」和「不稳定」两个问题，而且**新增内置工具时不会有人想起去改测试 env**。所以修法不是补三个 env，而是把沙箱 `HOME` 改到临时目录——所有 `~/...` 路径一次性隔离，未来新增工具自动覆盖。

### ② 补断言：为什么能到 100%

`mcpverify.py` 只有 130 行，但集成用例只断言 `ok` / `tool_count`，所以：

- 握手常量（协议版本、clientInfo、通知方法）没人看 → 让夹具升级成「像真服务端那样校验客户端」，常量错就回 error；
- 错误文案没人看 → 直接断言「命令不存在」「无有效响应」，并钉住「空 stderr 不得拼出冒号」；
- http 分支（JSON / SSE / 纯文本 / 非法 UTF-8 / 不可达 / 自定义头）根本没测 → 用 `http.server` 起本地端点逐个覆盖；
- 默认超时 12s / 8s 是文档承诺 → 用 `inspect.signature` 钉住；
- 毫秒量纲（`*1000`）不可观测 → 让端点睡 50ms，断言 ≥ 40ms。

过程中被新判据逼出两个真 bug：

1. `_read_msg` 的 deadline 只「读前看一眼」，`readline()` 阻塞时永不返回 → 服务端不响应就把验证请求挂死（改成 `os.read` + `selectors`）。
2. `Popen` 只捕 `FileNotFoundError`，`args` 类型错会抛穿请求线程（补宽兜底）。
