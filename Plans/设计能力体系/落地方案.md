# AI 设计能力体系 · 落地方案

> 目标：在**任意项目**（新项目 / 已有项目）里，让 AI 产出有较高美观度与体验感的界面。
> 核实日期 2026-10-16 · 本文所有安装指令均已核实，未核实的已标注。

---

## 0. 总览：这套体系由什么组成

| 层 | 载体 | 解决什么 | 装在哪 |
|---|---|---|---|
| **能力层** | `design-guardrails` skill | 六步流程 + 通用禁止项 + 结构模式 + 场景定性 + 两个脚本 | `~/.workbuddy/skills/`（已建好） |
| **自动层** | 每个项目的 `AGENTS.md` / `CLAUDE.md` | AI 每次开工会自动读到硬规则 | 各项目根目录 |
| **真源层** | 每个项目的 `DESIGN.md` + `tokens.css` | 该项目的值 + 取舍 | 各项目根目录 |
| **强制层** | `lint_styles.py`（+ 可选 git hook） | 机检硬编码值 | 各项目 `scripts/` |
| **外部层** | Claude Code `/design` · Hallmark | 出方向 · 体检 | agent 侧 |

**核心分工**：能力带走（装一次全局），值留下（每个项目一份）。

## 4. 使用指南

### 4.1 新项目：从零到有规范（约半小时）

| 步 | 你说什么 | 会发生什么 |
|---|---|---|
| ① | 「给这个项目起一套设计规范」 | AI 问你两句：**用户是来完成任务还是被打动？同类页面会有很多个吗？** → 据此定基调，写进 DESIGN.md §0 |
| ② | — | （新项目跳过） |
| ③ | 「给首页出 3 版方向」 | 用 `/design` 生成多版画板 → **你挑一版** |
| ④ | 「按选定方向写规范」 | AI 把值填进 `tokens.css` 与 `DESIGN.md`，生成 `AGENTS.md` + 复制 lint |
| ⑤ | 「按规范实现这个页面」 | AI 写代码（已带基调与禁止项） |
| ⑥ | — | AI 自评六项 + 跑 lint；你 review |

**你实际做的只有两件事**：回答两个问题、挑一版方向。其余是 AI 与脚本的活。

### 4.2 已有项目：从盘点开始（约 1–2 小时，可分段做）

| 步 | 你说什么 | 会发生什么 |
|---|---|---|
| ① | 「这个项目是工具型还是展示型？」（AI 会问） | 定基调，写进 DESIGN.md |
| ② | 「盘点这个项目的界面规范」 | AI 跑 `audit_tokens.py` → 输出四类值频次 + 非网格间距 → **归纳成"高频=规范、低频=待决策"** |
| ② | 你逐项决策低频值 | 收敛 or 保留（保留的记进"已知偏差"） |
| ③ | 「现有界面出几版改造方向」 | 出方案供你挑 |
| ④ | 「更新规范」 | AI 收敛 tokens、补 DESIGN.md（含禁止项、结构模式） |
| ⑤ | 「按新规范改造 XX 页面」 | **定点升级，不推倒重来** |
| ⑥ | — | 自评 + lint |

**已有项目的纪律**：不推倒重来 · 不迁移框架 · **先固规范再动界面**。

### 4.3 日常：改一个页面的完整循环

```
说需求 → AI 读 DESIGN.md 与基调 → 写代码 → 自评六项 + 跑 lint → 你 review
                                              ↓ 不满意
                                    补一条规则进 DESIGN.md → 下次自动生效
```

**这就是规范"长出来"的机制**：每次不满意的决策都变成一条规则，规范越用越贴合你。

## 5. 三方分工与预期产出

| 你（人） | Agent | 系统（脚本 / hook） |
|---|---|---|
| 回答"像工具还是像落地页" | 按基调出多版方案 | 扫出现有代码里的隐含规范与异常值 |
| 挑一版方向 | 生成 3–4 版供选 | 机检硬编码色值 / 字号 / z-index |
| 决定低频值收敛还是保留 | 归纳结果、给出建议 | 提交时拦截（配了 hook 的话） |
| 确认规范定稿 | 写 tokens、写 DESIGN.md、写代码 | — |
| review 产出、说"这里不满意" | 自查六项、修 | — |
| 判断不满意要不要变成规则 | 把规则补进 DESIGN.md | — |

### 每步预期得到什么

| 步 | 产出物 |
|---|---|
| ① | DESIGN.md 里那句基调声明 |
| ② | 一份"实际在用值"的频次报告 + 修正后的 tokens |
| ③ | 选定的一版方向（含参考图） |
| ④ | `tokens.css` + `DESIGN.md` + `AGENTS.md` + `lint_styles.py` |
| ⑤ | 界面代码 |
| ⑥ | lint PASSED + 一次自评记录 + 更厚的规范 |

## 6. 维护

- **规范是长出来的**：每遇到一个不满意的决定 → 补一条进 `DESIGN.md §7 禁止项`。
- **值只在一处**：改颜色/字号只改 `tokens.css`，不在别处写第二遍。
- **存量债不隐藏**：做不到的写进"已知偏差"表，标注计划，不假装干净。
- **skill 更新**：改源仓库 `agent-skills/design-guardrails/` 即全局生效（8 处是软链，无需重装）；换机器时 clone 该仓库 + 跑一次 `./install.sh`。

## 7. 不装什么（附原因）

| 不装 | 原因 |
|---|---|
| 各类"设计系统生成器"（Aioli / Google Stitch 等） | 会产出第二套 token，与项目自己的真源打架 |
| `frontend-design`、Hallmark `build`、`repaint` | 追求"每页不同指纹"，与工具型应用要的一致性冲突 |
| 设计知识库类 MCP（Design Intelligence 等） | `recommend_design` 会整套覆盖你已定的取舍；其知识已按需提炼进 `structure-patterns.md` |
| 代码审查 / a11y 类 MCP | 缺的规则自己加进 `lint_styles.py` 更划算 |

1. **Claude Code `/design` 是 research preview**——能力与可用档位可能变，第③步已备好跨工具的替代方案（`make_gallery.py`），不依赖它。

   - `claude plugin marketplace add GWJian/claude-skills` + `claude plugin install ui-redesign@gwj-skills`（**该版本只生成文档，不改代码**）
   - 从 `rashee1997/ui-redesign` 取文件放入 skills 目录（会改代码，每步需批准）
   - `npx skills add https://github.com/boparaiamrit/skills-by-amrit --skill ui-ux-redesign`（第三方转载）
   
   结论：**先不必装**。它的深审计（312 条规则）等你有真实审计需求时再引；其核心机制（多版原型 + 挑方向、三个旋钮、"先有 DESIGN.md 再改造"）本体系均已覆盖。
