# v0.4 设计评审：Skills 与 MCP 一级模块

> 状态：**待确认（评审门）** · 2026-09-22 · 确认后进入开发
> 目标：把「skills 管理分发」「MCP 管理分发」做成与会话记录、长期记忆并列的一级模块，实现「远程源 → 本地库 → 分发到各目标」的完整闭环。

---

## 0. 结论摘要

1. **四个一级模块**：会话（sessions）/ 记忆（memory）/ Skills / MCP；统一顶部模块导航，后端模块注册表 + 各自路由前缀，配置级独立启停，模块间零隐式依赖。
2. **两段式数据流**：`远程 Git 源 →（拉取/更新）→ hub 本地库 →（分发）→ 各目标`。三段版本可对比：源 commit / 本地库版本 / 目标部署版本。
3. **安全默认**：永不静默覆盖用户的本地修改（冲突标记三选一）；永不自动 git commit/push（只写文件 + 出 diff）；凭据仅以 env 引用或 600 权限文件保存，日志全量脱敏。
4. **可回退**：本地库保留上一版本快照，分发前自动备份被覆盖文件，一键回退。
5. **MCP 验证**：内置 MCP 协议握手（stdio initialize + tools/list / http 探测），写入后可"验证连接"并记台账。
6. **无现成对标**：生态中 `npx skills`（拉取安装）、`add-mcp`（单次写入配置）都只管"一次性动作"，**没有**带版本快照/台账/冲突处理/回退/统一 UI 的枢纽——这正本模块的定位。

## 1. 背景与现状盘点（本机实测）

### 1.1 Skills 现状（本机）

| 目录 | 数量 | 说明 |
|---|---|---|
| `~/.agents/skills/` | 35 | 跨工具通用位（npx skills 惯用落点） |
| `~/.claude/skills/` | 10 | Claude Code 全局 |
| `~/.config/opencode/skills/` | 9 | OpenCode 全局 |
| `~/.codex/skills/` | 1 | Codex 全局 |
| `~/.openclaw-autoclaw/skills/` | 44 | OpenClaw 运行时（不在本模块管辖，只读展示） |

- 格式：`SKILL.md` + YAML frontmatter（`name` / `description`），目录即技能包；GitNexus 系列同时存在于 claude/opencode 两处——**重复分发已经发生，但没有版本与台账管理**。
- 无版本清单文件：版本只能从 Git（源）或内容哈希（本地）推导 → 设计上以「源 commit + 内容树哈希」作为版本主键，可选支持 skill 自带 `version` 字段覆盖。

### 1.2 MCP 现状（本机）

| 工具 | 配置文件 | 现有条目 |
|---|---|---|
| Claude Code | `~/.claude.json`（全局） / 项目 `.mcp.json` | firecrawl, gitnexus, agentmemory |
| Codex | `~/.codex/config.toml`（全局） / 项目 `.codex/config.toml` | agentmemory |
| OpenCode | `~/.config/opencode/opencode.json`（mcp 段） | firecrawl, gitnexus, agentmemory |
| Cursor | `~/.cursor/mcp.json`（全局） / 项目 `.cursor/mcp.json` | （已安装，未配置） |

- 三家配置格式各不相同（JSON / TOML），同一条目在三处手工复制粘贴——**分发的价值已被验证，但缺管理**。

### 1.3 生态调研结论

| 工具 | 能力 | 缺口（我们补什么） |
|---|---|---|
| `npx skills add owner/repo` | 从 GitHub 拉 skill 写到各工具目录 | 无版本快照、无回退、无冲突处理、无台账、无分发目标管理、无 UI |
| `add-mcp`（neon-solutions） | 单命令把 MCP 写入 20+ 工具配置 | 一次性动作；无源仓库概念、无版本/更新/回退、无台账 |
| `agent-rules-sync`（PyPI） | 规则/skills/设置/MCP 跨工具实时同步 | 同步的是"当前机器状态"，无远程源版本管理 |
| `agentmemory connect` | 把记忆服务写入各工具 MCP 配置 | 专用单服务，无通用 MCP 目录管理 |

**结论**：拉取与写入这两个"动作"生态已有；缺的是**版本化的源→库→目标治理**。本模块按此定位设计。

- 配置存 `config` 表：`modules.enabled.skills` 等（默认全开）。
- 禁用效果：UI 隐藏入口；该模块路由统一返回 `503 {module disabled}`；其他模块不受影响（启动自检覆盖：禁用任一模块跑全量回归）。

## 5. 数据模型

### 5.1 新增表（DDL 要点）

```sql
sources(id PK, kind TEXT,           -- 'skills' | 'mcp'
        name TEXT, url TEXT, branch TEXT DEFAULT 'main', subdir TEXT,
        auth_ref TEXT,              -- 'env:GITHUB_TOKEN' | 'file:<path>' | NULL
        enabled INT DEFAULT 1, poll_min INT DEFAULT 0,   -- 0=不定时
        last_sync_at TEXT, last_commit TEXT, last_error TEXT,
        UNIQUE(kind, name));

snapshots(id PK, source_id INT, commit TEXT, taken_at TEXT, note TEXT,
          item_count INT, catalog_json TEXT);              -- 每次成功拉取的完整目录

items(id PK, source_id INT, kind TEXT, name TEXT, path TEXT,  -- 源内相对路径
      source_hash TEXT,           -- 目录树哈希（sha256, 排序后文件列表+内容）
      version TEXT,               -- manifest version 或 commit 短哈希
      meta TEXT,                  -- JSON：description 等（SKILL.md frontmatter / mcp 条目）
      UNIQUE(source_id, name));

registry_items(id PK, kind TEXT, name TEXT UNIQUE,
      source_id INT NULL, version TEXT, hash TEXT, updated_at TEXT,
      prev_version TEXT, prev_hash TEXT);                 -- 上一版本锚点（回退用）

targets(id PK, name TEXT, scope TEXT, -- 'global'|'repo'
        tool TEXT,                  -- claude|codex|opencode|cursor|plain
        path TEXT, writable INT, enabled INT DEFAULT 1, created_at TEXT);

deployments(id PK, item_kind TEXT, item_name TEXT, item_version TEXT,
      target_id INT, deployed_hash TEXT, deployed_at TEXT, status TEXT,
      UNIQUE(item_kind, item_name, target_id));           -- 当前部署态（幂等锚点）

ops(id PK, ts TEXT, module TEXT, action TEXT,
    item_kind TEXT, item_name TEXT, item_version TEXT,
    source_id INT NULL, target_id INT NULL,
    status TEXT,                  -- ok | failed | skipped | conflict
    reason TEXT NULL, detail TEXT);
CREATE INDEX idx_ops_filter ON ops(module, ts DESC);
```

### 5.2 三段版本与哈希

| 段 | 版本表示 | 来源 |
|---|---|---|
| 源 | commit 短哈希 + 条目树哈希 | git |
| 本地库 | registry_items.version + hash | 拉取时写入 |
| 目标 | deployments.deployed_hash | 分发时写入 |

- **幂等**：分发前先算目标现状哈希；与将写入内容一致 → `skipped(already-current)`，不落盘。
- **冲突**：部署后目标文件被手改（现哈希 ≠ deployed_hash）且要再分发 → `conflict`，不覆盖，三选一。
- **回退**：`registry/.versions/<name>/<ts>/` 保留上一版本内容；回退 = 内容还原 + 重新分发。

## 6. 核心流程与状态机

### 6.1 源生命周期

```
[未配置] → 添加(测试连通) → [就绪] → 拉取 → [已同步(commit, 快照)] → 定时/手动再拉取 → ...
                ↑ 失败(凭据/网络/清单非法) → [错误(原因, 可重试)] → 重试
```

### 6.2 条目生命周期（skills 与 mcp 对称）

```
源侧:   [发现] → [快照定版]
本地库: [未安装] → 更新到本地 → [已安装 vX]
                      ↑ 有新版 → [可更新 vY]
                      ↑ 本地被改 → [本地修改]
                      ↑ 目标被改 → [冲突]
操作:   更新(增量) / 回退(上一版) / 查看 diff / 移除
分发:   [选择目标] → dry-run diff → 分发 → 逐条 [ok/failed/skipped/conflict]
                      ↑ 失败 → 重试(单条/批量)
```

### 6.3 拉取算法（增量）

1. `git -C sources/<id> fetch --prune origin <branch>`（首次 `clone --filter=blob:none`）。
2. `git reset --hard FETCH_HEAD` 到源缓存（源缓存归 hub 所有，无用户修改，reset 安全）。
3. 解析目录 → 条目清单（skills: `**/SKILL.md` 根目录为条目；mcp: 目录内 `mcp/*.json` 或根 `mcp.json` 的多条目文件）。
4. 逐条算树哈希；与 `last_commit` 快照对比 → 产出 `added/changed/removed` 清单。
5. 写 `snapshots` + 更新 `items`；失败（清单非法/空目录/解析异常）→ 保留旧快照，`last_error` 记录，本次不推进 commit 指针（下次同 commit 幂等重放）。

### 6.4 分发算法（目录型 = skills；文件节型 = MCP）

**skills（目录型）**：
1. 计算内容哈希；查 `deployments`：同哈希 → skip。
2. 目标目录检查已有文件：与 deployed_hash 对比检测手改 → 冲突（默认停）。
3. 写入策略：逐文件清单 diff（新增/覆盖/删除仅限"我们上次落盘的文件"，白名单由 `deployments` 的托管文件清单保证）——**不整目录删除，绝不触碰用户文件**。
4. 原子性：先写 `<dest>/.hub-tmp-<rand>/` 再逐文件 rename 替换；被覆盖文件先备份到目标侧 `.hub-backup/<ts>/`。
5. 写 `deployments` + `ops`。

**MCP（配置节型）**：
1. 解析目标文件（JSON 直接读写；TOML 用受管块标记 `# >>> hub:managed: <name> <<<` 文本级替换）。
2. 已有同名条目：值与库值一致 → skip；不同且非我方写入（无标记）→ 冲突。
3. 写前 `cp` 备份；原子写（tmp+rename）；env 值支持 `${VAR}` 占位符透传，不解析明文。
4. 写 `deployments` + `ops`。

### 6.5 MCP 验证协议

- **stdio**：spawn `command args`（env 注入），写 `initialize`（JSON-RPC，协议版本 2024-11-05）→ 读响应 → `notifications/initialized` → `tools/list` → 统计工具数 → 关闭。超时 10s，全程输出脱敏。
- **http**：POST `initialize` 到 url（携带 headers），检查响应结构 → 报告 serverInfo。
- 结果：`{name, transport, server_name, server_version, tool_count, latency}` 入台账。

## 7. 接口定义（REST · 要点）

```
GET    /api/modules                          # 模块注册表 + 启停状态 + 健康
POST   /api/modules/{id}/toggle              # {enabled}

# —— Skills ——
GET    /api/skills/sources                   POST /api/skills/sources
PATCH  /api/skills/sources/{id}              DELETE /api/skills/sources/{id}
POST   /api/skills/sources/{id}/pull         # 拉取+快照；返回 added/changed/removed
GET    /api/skills/sources/{id}/items
GET    /api/skills/registry                  # 本地库（按状态筛选：installed/update-available/local-modified/conflict）
POST   /api/skills/registry/update           # {names:[], source_id} 源→本地库（增量+快照留档）
POST   /api/skills/registry/rollback         # {name}
GET    /api/skills/item/{name}               # 详情（SKILL.md 内容、版本、部署位置列表）
GET    /api/skills/diff                      # ?name=&vs=source|target&target_id=
GET    /api/skills/targets                   POST /api/skills/targets ...
POST   /api/skills/distribute                # {names, target_ids, dry_run} → 逐条结果

# —— MCP（与 Skills 对称）——
GET/POST/PATCH/DELETE /api/mcp/sources[/{id}]   POST .../pull
GET    /api/mcp/registry                     POST /api/mcp/registry/update  /rollback
POST   /api/mcp/distribute                   # {names, target_ids, dry_run}
POST   /api/mcp/verify                       # {name} → 握手结果

# —— 通用 ——
GET    /api/ops                             # 筛选：module/status/target_id/since/q + 分页
GET    /api/ops/export?format=csv|json
GET    /api/doctor
```

统一响应：`{ok, data|results[], error}`；`results` 逐条含 `{item, target, status, reason}`。

## 8. 交互与 UI 设计

### 8.1 导航（一级模块）

### 8.2 各视图要点

**Skills 视图（三栏，沿用现有布局骨架）**
- 左栏：源列表（+添加源；每源显示 状态点/最近同步/条目数）+ 目标列表（工具全局/项目仓库，可添加）。

## 9. 内部实现逻辑（关键决策记录）

| 主题 | 决策 |
|---|---|
| 源缓存 vs 本地库 | 两级分离：`sources/<id>/` 是 git 缓存（hub 全权所有，reset 安全）；`registry/` 是用户可读可改的本地库（增量更新与回退的锚点） |
| 凭据 | `env:VAR` 或 `file:path`（chmod 600 检查）；git 调用经临时 ASKPASS 注入，URL 中的 token 只在子进程内存出现；所有日志/接口输出经 `mask()` 脱敏 |
| 并发 | 每源一锁（拉取串行）、分发全局锁（防交叉写）；批量操作 = 逐条事务（单条失败不阻塞其余），最终汇总 |
| 事务边界 | 文件操作"逐目标单项"为事务单元：备份 → 原子写 → 记录；任一步失败回滚该项（恢复备份），其余项继续 |
| 幂等 | 三向哈希（源/本地/部署）+ `deployments` 唯一键 → 重复操作自然收敛为 skip |
| TOML | 用受管块标记做文本级 merge（避免引入 toml 依赖，Python 3.9 无 tomllib）；写入前整文件备份 |
| 删除物 | 仅删"曾被本系统落盘且记录在托管清单中"的文件；其余一律不碰 |
| 写回远程 | 不实现（接口位保留）；任何 git 写操作默认关闭 |
| 大源 | 条目解析流式处理；diff 按需计算（懒加载）；数百条量级直接全量，超 1000 条时分页与分批 |
